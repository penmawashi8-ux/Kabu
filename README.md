# kabu — 楽天証券の株価トリガー自動売買ボット

「**〇〇円まで下がったら買う / 〇〇円まで上がったら売る**」を自動で実行する Python 製のボットです。
楽天証券の **マーケットスピードII RSS**（Excel アドイン）経由で株価を取得し、発注します。

```
株価トリガー到達 → リスク検査 → RSS 経由で発注 → 約定確認 → 状態更新 → 記録
```

## かかるお金

| もの | 費用 |
|---|---|
| 楽天証券の口座 | 無料 |
| マーケットスピードII 本体 | 無料 |
| マーケットスピードII **RSS**（Excel アドイン） | 無料 |
| Python・本ソフト | 無料 |
| **Windows PC（常時起動）** | 手持ちのもの |
| **Microsoft Excel** | 有料（RSS が Excel アドインのため必須） |
| 売買手数料・税金 | 楽天証券の料金体系どおり |

つまり「PC 以外は無料」ですが、**Excel だけは別途必要**です（LibreOffice や Google スプレッドシートでは RSS が動きません）。

## 先に検討すべき: そもそもプログラムが要らないケース

やりたいことが「1 回だけ、〇〇円で買って〇〇円で売る」なら、
楽天証券の **特殊注文（逆指値・ツイン指値・IFD/OCO 系）** で完結します。
そちらのほうが安全です — PC を起動しておく必要がなく、ネット断や PC の再起動と無関係に証券会社側で執行されます。

本ボットが役に立つのは次のような場合です。

- 同じ値幅の売買を **何往復も繰り返したい**（`max_cycles`）
- 複数銘柄のルールを **1 か所で管理し、記録を自動で残したい**
- 発注の上限や連射防止など、**自前の安全弁を挟みたい**
- 将来もっと複雑な条件（指標・時間帯・板情報）に**育てていきたい**

## まずシミュレーションから

楽天証券の口座も Excel も無しで、いきなり動きを見られます。**証券会社には一切接続しません。**

### いちばん手軽な方法: `simulator.html` をダブルクリック

インストールも Python も要りません。リポジトリの **`simulator.html`** を
ダウンロードしてブラウザで開くだけです（[GitHub の Raw リンクから保存](
https://github.com/penmawashi8-ux/Kabu/raw/claude/rakuten-securities-auto-trading-c4nmiz/simulator.html)）。
ネットに繋がっていなくても動きます。

この 1 枚版は**ブラウザの中だけで動くお試し版**です。銘柄の追加も推奨値も
スライダーも一通り使えますが、株価は擬似のみで、記録はファイルに残りません。
本物の売買ロジック（`strategy.py` / `risk.py`）を回したいときは、下の `kabu play` を使ってください。

> `simulator.html` は `src/kabu/dashboard.html` から自動生成しています。
> 画面を直したら `python tools/build_standalone.py` で作り直してください
> （忘れるとテストが落ちます）。

### 本物のロジックで動かす: `kabu play`

```powershell
git clone https://github.com/penmawashi8-ux/Kabu.git
cd Kabu
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"

kabu play -c config.simulate.yaml
```

ブラウザで `http://127.0.0.1:8765/` を開くと、株価チャートと売買トリガーの線が出ます。
**起動しただけでは何も動きません。** 動かすのはあなたです。

- **右端のスライダーを上下にドラッグ** すると株価が動きます。買いラインを割ると、その場でボットが買い注文を出します
- **「自動で株価を動かす」ボタン** を押すと株価がひとりでに揺れ続け、放っておくと売買が繰り返されます
- 売買記録には「なぜその注文を出したか」「なぜ見送ったか」が 1 行ずつ残ります

### 株価をどこから取るか

```powershell
kabu play -c config.simulate.yaml                  # 擬似株価（既定・ネット不要）
kabu play -c config.simulate.yaml --source real    # 実際の株価（日足）を再生
kabu play -c config.simulate.yaml --source rss     # マーケットスピードII のリアルタイム値
```

| `--source` | 株価 | いつの値段か | 必要なもの |
|---|---|---|---|
| `sim`（既定） | 作り物 | — | なし |
| `real` | **実際の値段** | 過去（日足を早送り再生） | ネット接続 |
| `delayed` | **実際の値段** | **いまの値段。ただし約 20 分遅れ** | ネット接続 |
| `rss` | **実際の値段** | **リアルタイム** | 楽天証券口座 + Excel + マーケットスピードII |

画面の上部に出どころのバッジが出るので、いま見ている株価が本物かどうかは常に分かります。

**`--source real` について。** 無料で手に入る日本株の株価は基本的に日足（1 日 1 本）です。
本ツールはその 1 日を「寄り → 高値 → 安値 → 引け」の 4 点でなぞりながら早送りします。
その日に実際に付いた値段なので、高値・安値がトリガーに当たったかどうかは正しく再現されます。

```powershell
kabu play --source real --speed 8              # 倍速
kabu play --source real --provider yahoo       # 取得元を変える（stooq が既定）
```

一度取得したデータは `.kabu_cache/` に残るので、次からはネット無しでも再生できます。
取得に失敗した場合は理由を表示して擬似株価で起動します（起動しないことはありません）。

> **日足ゆえの注意**: 値動きが 1 日単位で飛ぶため、損切りラインを大きく下抜けた値段で
> 約定することがあります。実際の相場でも寄り付きのギャップで同じことは起きますが、
> 日足の再生ではその幅が誇張されて見えます。

### 株価をリアルタイムで動かしたい場合

先に結論を書きます。**日本株のリアルタイム株価は、無料では証券会社の口座経由でしか手に入りません。**
一般に公開されている無料の配信は、どれも 20 分ほど遅延しています。これは本ツールの制約ではなく、
取引所の配信ルールによるものです。選択肢は次のとおり。

| 方法 | 遅延 | 費用 | 条件 |
|---|---|---|---|
| **マーケットスピードII RSS**（`--source rss`） | **なし** | 無料 | 楽天証券口座・Windows・Excel |
| kabuステーション API（auカブコム証券） | **なし** | 無料 | auカブコム口座・Windows・常駐アプリ |
| 無料の公開配信（`--source delayed`） | 約 20 分 | 無料 | ネット接続だけ |
| 有料のデータ配信業者 | なし | 有料 | 契約 |

**いま口座がないなら `--source delayed`。** 20 分遅れですが値段は本物で、
場中はちゃんと動きます。口座も申込も要りません。

```powershell
kabu play -c config.simulate.yaml --source delayed
kabu play -c config.simulate.yaml --source delayed --poll-live 60   # 取得間隔を延ばす
```

「再生する」を押すと取得を始め、既定で 30 秒ごとに現在値を取り直します
（取得元に負荷をかけないよう、10 秒より短くはできません）。
**動くのは立会時間中（9:00〜11:30 / 12:30〜15:30）だけ**です。
それ以外の時間は値段が止まって見えますが、故障ではありません。

**口座を作ったあとは `--source rss`。** マーケットスピードII にログインしていれば、
実弾モードとまったく同じリアルタイム株価で動きます。**発注だけがシミュレーション**なので、
本番投入の直前確認にはこれが一番近い形です。

いずれの場合も、画面上部のバッジに出どころが出ます（`実際の株価（遅延） 14:45` のように、
その値段がいつ時点のものかも表示します）。

### 銘柄とルールを画面から決める

上部のフォームで、銘柄・株数・買い・売り・損切りをその場で設定できます（最大 12 銘柄）。
主要銘柄はプルダウンから選べます。リストにない銘柄はコードを直接入力してください。

**買い・売り・損切りには推奨値が入ります。** 入力した「開始価格」を基準に、

| 値幅の狙い | 買い | 売り | 損切り |
|---|---|---|---|
| 控えめ | −2% | +2% | −3.6% |
| 標準 | −4% | +4% | −7.2% |
| 大きめ | −8% | +8% | −14.4% |

推奨値はあくまで出発点です。3 つとも自由に書き換えられます（各入力の下に
「開始価格から何 %か」と推奨値が出るので、どれだけ離したか分かります）。

> **開始価格は実際の株価ではありません。** シミュレーション上の出発点として使う数字です。
> 本物に近づけたいときは、証券会社の画面に出ている値を入れてください。

入力の検証は設定ファイルとまったく同じコード（`config.py` の `Rule.from_dict`）を通ります。
「売りが買いより安い」「損切りが買いより高い」といったルールは同じ日本語のメッセージで弾かれるので、
**画面で通ったルールはそのまま `config.yaml` に書けます。**

各銘柄の「ルールを変える」「外す」で後から編集・削除できます。
ルールを変えるとシミュレーションは最初からやり直しになります。

**「config.yaml にも保存する」にチェックが入っていれば、追加・更新・削除のたびに
`-c` で指定した設定ファイルへ自動で書き戻されます。** 書き換えるのは `rules:` の
中身だけで、他の設定やコメントはそのまま残ります。手で `config.yaml` を
書き写す必要はもうありません（チェックを外せば従来どおり画面上だけの
お試しになります）。このボタンはサーバー版（`kabu play`）だけの機能で、
`simulator.html` 単体版では出ません（ブラウザだけで完結していて、
保存先のファイルにアクセスできないため）。

画面に出ているのは飾りではありません。実弾モードで動くのと**同じ売買ロジック**（`strategy.py` と `risk.py`）を回していて、発注先だけが `PaperBroker` に差し替わっています。

ルールを変えて試すには `config.simulate.yaml` の `rules:` を編集して、再起動してください。

| オプション | 意味 |
|---|---|
| `--port 8765` | 待ち受けポート |
| `--lan` | 同じ Wi-Fi のスマホなどから開けるようにする |
| `--market-hours` | 立会時間内でしか動かさない（既定はいつでも動く） |

## 口座区分と株価取得は別物です

よくある誤解なので明記します。

| | 口座区分（特定 / 一般 / NISA）に関係するか |
|---|---|
| **株価の取得**（RSS のリアルタイム配信） | **関係しません** |
| **発注**（実際に買う・売る） | 関係します |

口座区分は**発注するときのパラメータ**です。株価の配信は「楽天証券の口座を持っていて
マーケットスピードII にログインしている」ことだけが条件で、どの口座区分で取引するか、
そもそも取引するかどうかとは無関係です。

つまり **一度も発注しなくても、リアルタイム株価は取得できます。**

```powershell
kabu play -c config.simulate.yaml --source rss
```

これは「株価はリアルタイムの本物・発注はシミュレーション」という組み合わせです。
`kabu play` は常に `mode: paper` で動くため、取引パスワードも注文一覧シートも要りません。
NISA 枠にも特定口座にも一切触れずに、本物の値動きでルールを検証できます。

> **マーケットスピードII の利用条件は念のため確認してください。** 口座があれば無料で
> 使えるはずですが、利用申込が必要です。また過去には取引実績を条件にしていた時期も
> あるため、現在の条件は楽天証券のページでご確認ください。

## NISA 口座について

**このボットを NISA 枠で動かすことは勧めません。** 理由は 3 つあります。

1. **年間の投資枠をすぐ使い切ります。** NISA の枠は買付のたびに消費され、
   売っても枠が戻るのは翌年です。100 株 3,000 円（30 万円）の売買を繰り返すと、
   成長投資枠 240 万円は 8 回の買付で尽きます。本ボットは往復を繰り返す前提です
2. **損益通算・繰越控除ができません。** NISA 口座の損失は他の利益と相殺できず、
   翌年以降にも繰り越せません。本ボットは損切りを前提にしているので、
   この不利がそのまま効きます
3. **短期売買では非課税の利点がほとんど出ません。** NISA の利点は長く持って
   利益を伸ばしたときの非課税であって、小さな値幅の往復では活きません

**実弾に進むなら特定口座を使ってください。** `config.example.yaml` の
`account_type` は最初から `特定` になっています。NISA を指定した場合は
起動時に警告が出ます（止めはしません。判断はご自身で）。

> **NISA 口座だけを持つことはできません。** NISA 口座は課税口座（特定口座・一般口座）に
> 付随して開設されるため、楽天証券に NISA 口座があるなら特定口座も一緒にあるはずです。
> 使っていないだけの可能性が高いので、証券会社の画面で確認してください。

なお、**シミュレーターと株価の取得には口座区分は一切関係ありません。**
`kabu play` はどの口座を持っていても（持っていなくても）動きます。

## セットアップ

### 1. 楽天証券側

**マーケットスピードII の利用料は無料です。** 2019 年 6 月 24 日に無条件で無料化され、
取引実績・資産残高・信用口座の有無などの条件はありません。ただし**利用申請が必要**です。

1. 楽天証券に総合口座を開設する（NISA 口座があるなら既にあります）
2. **マーケットスピードII の利用申請**をする
   — ウェブにログインして申請、またはマーケットスピードII のログイン画面から申請。
   土日も手続きでき、**申請当日から使えます**。利用期限は自動で 1 年ごとに更新され、
   再申請は不要です（申請の取消しはできません）
3. マーケットスピードII をダウンロードしてインストールし、ログインする
4. **Excel に RSS アドインを登録する**（下記）

#### RSS アドインの登録（初回だけ）

アドインのファイルはインストール時に次の場所へ置かれます。

```
C:\Users\(ユーザー名)\AppData\Local\MarketSpeed2\Bin\rss
```

Excel を開き、**ファイル → オプション → アドイン** を選択。下部の「管理」が
**Excel アドイン** になっていることを確認して **設定** を押します。
**参照** から上のフォルダを開き、次の **2 つ**を順に登録してください。

| ファイル | 備考 |
|---|---|
| `MarketSpeed2_RSS_32bit.xll` または `MarketSpeed2_RSS_64bit.xll` | **Excel のビット数に合うほう**を選ぶ |
| `MarketSpeed2_RSS_VBA.xlam` | こちらは共通 |

「有効なアドイン」に 2 つともチェックが入っていれば完了です。登録は 1 回だけで、
以降は不要です。

#### どちらのビット数を選ぶか

**`kabu doctor` が判定して、登録すべきファイル名を名指しします。**

```
Excel のビット数  : 64 ビット　［レジストリ（Office クイック実行の構成）］
  登録する 2 つ   : MarketSpeed2_RSS_64bit.xll
                    MarketSpeed2_RSS_VBA.xlam
  アドインの場所  : C:\Users\you\AppData\Local\MarketSpeed2\Bin\rss
```

自分で確認する場合は、Excel で **ファイル → アカウント →
「Microsoft Excel のバージョン情報」**（ショートカット: `Alt` → `F` → `D` → `A`）。
タイトル行の末尾に「32 ビット」「64 ビット」と出ます。

> **見るのは Windows のビット数ではなく Excel のビット数です。**
> 64bit の Windows に 32bit の Excel が入っていることは普通にあります
> （Office は長らく 32bit 版が既定でした）。ここを取り違えると、
> 正しいファイルを選んだつもりで読み込めません。

> RSS は「マーケットスピードII にログインしている間だけ」動きます。ボット稼働中は起動したままにしてください。

最低限、`excel.workbook` のパスと `rules:` を自分の銘柄に書き換えます。

```yaml
rules:
  - id: toyota

    buy_at: 2800        # この値以下になったら買う
    sell_at: 3000       # この値以上になったら売る

```

### 4. Excel ブックの用意

```powershell
kabu init-sheet          # QUOTES / ORDERS の 2 シートを持つ雛形を作る
```

- **QUOTES シート** — ボットが起動時に `=RssMarket(...)` を自動で書き込みます。手を触れる必要はありません。
- **ORDERS シート** — ここに「注文一覧」を表示させてください。RSS の注文一覧関数を A1 に入力すると、見出し行つきの表が展開されます。ボットは**この表を約定確認の唯一の情報源**として読みます。

`config.yaml` の `rss.order_columns` で、シートの見出し文字列と内部項目を対応づけます。実際の見出しが既定値と違う場合はここを書き換えてください。

## 過去のデータで試す（バックテスト）

「昨日の値動きでこのルールを回していたら、どうなっていたか」を確かめられます。
**発注は一切しません。** 実弾モードと同じ売買ロジック（`strategy.py` / `risk.py`）を、
実際に付いた値段で回します。

```powershell
kabu -c config.yaml backtest                    # 直近の取引日 1 日ぶん
kabu -c config.yaml backtest --days 20          # 直近 20 営業日
kabu -c config.yaml backtest --since 2026-08-01 # この日から今日まで
kabu -c config.yaml backtest --provider yahoo   # 取得元を変える（既定は stooq）
```

出力はこんな形です。

```
=== 2026-08-28 のペーパートレード結果 ===

  7203.T 2026-08-28  寄り 2,900.0 / 高値 3,050.0 / 安値 2,750.0 / 引け 3,010.0

  売買（買って売るまでを 1 件）
    [toyota] 7203.T 100株  買 2,750.0 → 売 3,010.0（売りライン）  ＋26,000 円

  発注 2 件 / 約定 2 件
  実現損益: +26,000 円（手数料・税金は含みません）
```

安全弁で発注を見送った場合も理由つきで出ます（`1 回の約定代金 340,000 円が上限
300,000 円を超えます` など）。**株数と値段の組み合わせが `risk:` の上限に当たっていて
1 度も買えていない、といった設定ミスはここで見つかります。**

> **日足ゆえの限界。** 無料で手に入るのは日足なので、その日の値動きは
> 「寄り → 高値 → 安値 → 引け」の 4 点でなぞります。高値と安値のどちらが先だったかは
> 日足からは分かりません。**トリガーに当たったかどうかは正しく再現されますが、
> 往復の回数は実際とずれることがあります。**
>
> また、秒単位の時間軸を前提にした安全弁（`max_price_deviation_pct` と
> `pending_timeout_sec`）は、日足の再生では常に誤作動するため、バックテストの間だけ
> 無効化しています。1 回の発注額や 1 日の発注件数の上限は本番と同じに効かせます。

## どの値幅設定が良かったかを探す（`kabu optimize`）

値幅の候補を総当たりし、過去データで成績順に並べます。**発注はしません。**

```powershell
kabu -c config.yaml optimize                          # config.yaml の銘柄で探索
kabu -c config.yaml optimize --symbols 7203.T,9432.T  # 銘柄を指定
kabu -c config.yaml optimize --segment 20 --holdout 60
```

### この探索が守っているもの

**1. 期間を 2 つに割り、片方は選定に一切使いません。**

| | 使い道 |
|---|---|
| 探索期間 | 候補を総当たりして良いものを選ぶ。**後知恵なので実力ではありません** |
| 検証期間（既定 直近 60 営業日） | 選んだあとで初めて触る。**実運用に近いのはこちら** |

探索期間で大勝ちして検証期間で沈む設定は、過去に合わせ込んだだけ（過剰適合）です。

**2. 期間を短く区切り、区間ごとに線を引き直します（既定 20 営業日）。**

このボットの売買ラインは「2,800 円で買う」という固定の値段なので、株価が離れれば
置き去りになります。1 年ぶんを一続きで測ると、値幅の良し悪しではなく
**株価がどれだけドリフトしたか**を測ることになってしまいます。

**3.「安定して」の中身は勝ち区間の割合で見ます。** 合計損益だけでは、1 区間の
大当たりで持ち上がっていても見分けられません。最悪の区間も併記します。

**4. 日足では確かめようのない設定は最初から外します。** 買いと売りの間隔、または
買いと損切りの間隔が「1 日の値幅」より狭い候補は、4 点なぞりの中で何往復もして
しまい、実際にそうなるかは分足を見ないと分かりません。

**5. 持ちっぱなし（buy & hold）の成績を必ず並べます。** それに負けているなら、
売買を繰り返す意味はありません。

### 出力の例

```
■ 6758.T   基準価格 1,760 円 × 100 株 = 175,962 円
  1 日の値幅（中央値）2.4% より広い 66 通りを、20 営業日ずつの区間で総当たり
------------------------------------------------------------------------------
値幅の設定                        探索期間（選定に使用）        検証期間（本命）
買 -2.0% / 売 +6.0% / 損切 -6.0%  -149,442円 勝ち区間19% 60回   +11,766円 勝ち区間67% 5回

  検証期間（1 位の設定）: +6.7%（+11,766 円 / 投下 175,962 円）  最悪の区間 -17,368 円
  同じ期間を持ちっぱなし  : +3.7%
```

> **手数料と税金は含まれていません。** 往復するほど不利になります。
> また、**過去にうまくいった設定がこれから儲かる保証はありません。**
> この探索でできるのは「明らかに駄目な設定を捨てること」までです。

## 安全弁

自動売買で最も怖いのは「ロジックのミスで想定外の注文を連射すること」です。
戦略の判断とは**独立に**、発注直前で必ず以下を検査します（`config.yaml` の `risk:`）。

| 項目 | 内容 |
|---|---|
| `max_orders_per_day` | 1 日の発注件数の上限 |
| `max_notional_per_order` | 1 回の約定代金の上限 |
| `max_notional_per_day` | 1 日の買付総額の上限 |
| `min_seconds_between_orders` | 連射防止（最低待ち時間） |
| `max_price_deviation_pct` | 前回値から極端に飛んだ値段は誤配信とみなして無視 |
| `quote_max_age_sec` | 古い株価では発注しない |
| `pending_timeout_sec` | 注文が約定しないまま放置されたらルールを停止し人間を待つ |
| `kill_switch_file` | このファイルの存在で即停止 |

さらに構造として、

- **二重発注防止** — 発注中のルールは、約定/取消が確認できるまで次の注文を出しません
- **状態の永続化** — 発注のたびに `state.json` に保存。PC が落ちても再起動時に注文中の状態から再開します
- **売り注文の失効は自動復帰しない** — 建玉が残っている可能性があるため `HALTED` にして人間の確認を待ちます
- **立会時間の判定** — 東証の時間外・昼休み・土日・設定した祝日には発注しません
- **引け間際は新規建てしない** — `trade_cutoff`（既定 15:20）以降は買いを出しません

## 記録

- `journal.csv` — 1 行 1 イベント（ORDER / FILL / BLOCKED / HALT …）。Excel でそのまま開けます
- `logs/kabu.log` — 稼働ログ（5MB × 5 世代でローテーション）
- `state.json` — 現在の状態。触らないでください

## RSS の関数について

関数名・引数の並び・注文一覧の列見出しはバージョンによって差があるため、本ツールは
それらを**すべて `config.yaml` の `rss:` セクションに逃がして**あり、コードを書き換えずに追従できます。

### 株価取得（確認済み）

```
=RssMarket(A2, "現在値")     ← A2 に "7203.T" が入っている
```

本ツールが `QUOTES` シートに自動で書き込む式そのものです。`現在値` `現在値時刻` は
いずれも実在する取得項目なので、そのまま動くはずです。

### 発注（**要確認**）

現物注文の関数は `RssStockOrder` で、書式は次のとおりです。

```
RssStockOrder(発注ID, 発注トリガー, 銘柄コード, 売買区分, 注文区分, SOR区分,
              注文数量, 価格区分, 注文価格, 執行条件, 注文期限, 口座区分, …)

例: =RssStockOrder(1,1,4755,3,0,0,100,0,,1,,0)   → 100 株を成行で買い
```

> **未解決の問題があります。** 上の書式が示すとおり、`RssStockOrder` は
> **セルに書き込む関数**であって、VBA マクロとして呼ぶものではない可能性が高いです。
> 本ツールの `RssBroker.place_order` は `Application.Run` でマクロとして呼ぶ実装なので、
> **そのままでは発注が動かないおそれがあります。**
>
> `mode: live` に進む前に、必ず[公式の関数一覧 PDF](https://marketspeed.jp/guide/manual/ms2rss_function.pdf)
> で発注の呼び出し方を確認してください。売買区分・口座区分などのコード値の対応も
> この PDF にあります。
>
> **株価取得だけ（`kabu play --source rss`）ならこの問題は一切関係ありません。**
